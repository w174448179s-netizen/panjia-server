# 盘家智管 · 员工域（panjia-people）· 详细设计

> **版本：** V6.0（导入回迁版 · 落地版）
> **编制日期：** 2026 年 9 月
> **定位：** 基于《薪酬与收支架构设计 V1.8》§2.3/§10/§11.1 +《业务需求说明书 V4.2》+《AI 总规约 V3.0》，将 `panjia-people` 落地为可直接编码的详细设计。
> **V6.0 核心变更（导入回迁）：** 员工主数据 Excel 导入**回归本域**，不再经 `panjia-import`。本域复用 `common-import-util` 工具层做文件解析，**自建** `pj_people_import_batch` / `pj_people_import_raw` / `pj_people_import_issue` / `pj_people_import_template` 四张表，**业务落地单一大原子事务**，完整复用本域已有 Port-Adapter、`salary_fact` 闭开区间变更通用入口、`change_log` 审计；**不调用 import 域业务接口、不发布 import 域事件**。`panjia-import` 回退为纯单据域，两域**仅工具层复用、业务层不复用**。
> **前置条件：** 底座（RuoYi-Vue-Plus 6.x）、`panjia-contracts`、`common-import-util` 已完成。
> **依赖边界：** 本域是公共根，不依赖任何业务域；经 `port/` + `adapter/` 协作 RuoYi 底座；员工导入依赖 `common-import-util`（工具层）。
> **读者：** 编码负责人、实施顾问、payroll / commission 域开发者。

## 〇、核心约定（一次说清，后文不再重复）

### 0.1 一句话目标

> **管住"员工是谁、在什么部门、算薪事实是什么"，并把这些事实按时点冻结供下游算薪。**

### 0.2 事实 vs 规则（冻结）

| 类别 | 内容 | 归属 |
|------|------|------|
| **事实**（进 `salary_fact`，人身上） | 职级、状态、社保/公积金/商业/宿舍**是否缴**、兼职标记、师傅 | **本域** |
| **规则**（客户可配，不进人身） | 社保基数/比例、公积金金额/比例、兼职是否豁免、徒弟奖励上限、提点、底薪 | **payroll 域** |

> **换客户 = 只改规则 JSON，人身上 0 改动。**

### 0.3 岗位与角色模型（冻结）

| 结论 | 说明 |
|------|------|
| 岗位挂在**客户根节点**下 | 初始化已建（客户名参数化），所有门店共用同一 `post_id` |
| **岗位名 = 角色名** | `post_name → role_name` 同名匹配 |
| **多岗位 → 多角色** | `post_names` 用 `/` 分隔；每个岗位绑一条 `sys_user_post`，每个匹配到的岗位名绑一条 `sys_user_role`（**先清后绑，不取主岗位**） |
| 匹配不到角色 | **不绑、不报错**，HR 自行去 RuoYi 后台赋权 |
| `sys_role_dept` | **预置不改**，对账也不碰 |

### 0.4 初始化（已就绪，设计只做对齐）

根部门 + 岗位 + 角色 + 角色数据权限由初始化脚本建好（客户名参数化）。**本设计不重复定义脚本**，只依赖其产出：`rootDeptId`（配置项 `panjia.tenant.root-dept-id`）、`sys_post` 岗位集、`sys_role` 角色集。

### 0.5 菜单与权限

**一个「员工管理」菜单**（不拆分），HR 全权维护；算薪组只读。

### 0.6 三不原则

| 本域**负责** | 本域**不负责** |
|-------------|---------------|
| 员工档案、部门归属、算薪**开关** | 社保基数/比例、公积金金额/比例（→payroll 规则） |
| 岗位/角色绑定（经 Port） | "兼职是否豁免"等业务判断（→payroll 规则） |
| salary_fact 闭开区间变更 | 算薪参数配置、提点/底薪/扣点 |
| **员工主数据导入（本域自建）** | **业务单据导入（业绩/考勤/积分/费用 →import 域）** |
| 按员工+时点产出 Snapshot | 下游快照持久化（→消费域） |

### 1.1 `pj_people_employee`（员工基本信息，一人一行）

```sql
CREATE TABLE pj_people_employee (
    employee_id    BIGINT       PRIMARY KEY,   -- 雪花 ID（禁用自增）
    employee_code  VARCHAR(32)  NOT NULL UNIQUE, -- 工号（= sys_user.username）
    employee_name  VARCHAR(64)  NOT NULL,
    dept_id        BIGINT       NOT NULL,       -- 归属部门（= sys_user.dept_id）
    phone          VARCHAR(20),
    id_card        VARCHAR(64),                 -- AES 加密
    report_date    DATE,                        -- 报道时间
    hire_date      DATE         NOT NULL,       -- 入职时间（fact 生效日）
    leave_date     DATE,                        -- 离职时间（NULL=未离职）
    status         VARCHAR(16)  NOT NULL,       -- ACTIVE/PARTTIME/LEFT/PENDING
    mentor_employee_id BIGINT,                  -- 师傅员工 ID（NULL=无）
    remark         VARCHAR(512),
    user_id        BIGINT UNIQUE,               -- 关联 sys_user.id（导入后回填）
    version        INT          NOT NULL DEFAULT 0,  -- 乐观锁
    create_time    TIMESTAMP    NOT NULL DEFAULT NOW(),
    update_time    TIMESTAMP    NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_employee_dept ON pj_people_employee(dept_id);
```

> **无 `position`、无 `role_id`**——岗位/角色全部走 `sys_user_post` / `sys_user_role`。

### 1.3 `pj_people_salary_fact`（★ 算薪用，一项一条，闭开区间）

```sql
CREATE TABLE pj_people_salary_fact (
    id             BIGINT       PRIMARY KEY,
    employee_id    BIGINT       NOT NULL,
    fact_type      VARCHAR(16)  NOT NULL,   -- 8 类枚举
    value          VARCHAR(128) NOT NULL,   -- 按 fact_type 解析
    effective_date DATE         NOT NULL,   -- 生效（闭）
    expire_date    DATE,                    -- 失效（开，NULL=至今）
    change_field   VARCHAR(32)  NOT NULL,   -- 本次变更项（ALL=入职初始化）
    batch_id       BIGINT,                  -- 来源导入批次（可空=手工变更）
    create_time    TIMESTAMP    NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_fact_emp_type ON pj_people_salary_fact(employee_id, fact_type);
CREATE INDEX idx_fact_effective ON pj_people_salary_fact(employee_id, fact_type, effective_date, expire_date);
```

**fact_type 枚举（冻结 8 类）：**

| fact_type | value 含义 | 示例 |
|-----------|-----------|------|
| `LEVEL` | 职级 | `A2` |
| `STATUS` | 在职状态 | `ACTIVE` |
| `SOCIAL` | 社保是否缴 | `true` |
| `HOUSING` | 公积金是否缴 | `false` |
| `COMMERCIAL` | 商业保险 | `true` |
| `DORMITORY` | 宿舍 | `false` |
| `PARTTIME` | 兼职标记 | `false` |
| `MENTOR` | 师傅员工 ID | `1000148441` |

**时点取数：**

```sql
SELECT value FROM pj_people_salary_fact
WHERE employee_id = :empId
  AND fact_type   = :factType
  AND effective_date <= :point
  AND (expire_date IS NULL OR expire_date > :point)
ORDER BY effective_date DESC
LIMIT 1;
```

## 二、变更模型

### 2.1 通用变更方法（所有改动走这一个入口）

```java
/**
 * 结束旧记录 + 新增（闭开区间）；未变化的字段不动
 */
@Transactional
public void changeFact(Long employeeId, String factType, String newValue,
                       LocalDate effectiveDate, String changeField, Long batchId) {
    // 1. 结束当前活跃记录
    factMapper.expireActive(employeeId, factType, effectiveDate);
    // 2. 新增
    SalaryFact fact = new SalaryFact(employeeId, factType, newValue,
                                     effectiveDate, null, changeField, batchId);
    factMapper.insert(fact);
    // 3. 写 change_log
    changeLogMapper.insert(ChangeLog.of(employeeId, changeField, oldValue, newValue, effectiveDate, batchId));
    // 4. 刷新 record（当前态）
    recordMapper.refresh(employeeId);
}
```

### 2.2 入职 = 生成初始 fact

不单独初始化 —— **入职走导入或新增，为 8 个 fact_type 各生成一条**（`change_field = ALL`）。

### 2.3 修改员工 = 统一变化检测（★ 核心）

**不做独立调岗功能** —— 改部门/岗位/职级/状态都在"修改员工"里。

```java
@Transactional
public void updateEmployee(EmployeeDTO dto) {
    Employee old = employeeMapper.selectById(dto.getEmployeeId());

    // ① 归属部门变了 → 同步 sys_user.dept_id
    if (!old.getDeptId().equals(dto.getDeptId())) {
        employeeMapper.updateDept(dto.getEmployeeId(), dto.getDeptId());
        accountPort.updateDept(old.getUserId(), dto.getDeptId());
        changeLogMapper.insert(ChangeLog.of(...,"DEPT_CHANGE",...));
    }

    // ② 职位变了 → 重建岗位 + 角色（先清后绑，多岗位→多角色）
    if (!oldPostNames.equals(dto.getPostNames())) {
        accountPort.rebuildPostsAndRoles(old.getUserId(), dto.getPostNames());
        changeLogMapper.insert(ChangeLog.of(...,"POST_CHANGE",...));
    }

    // ③ 算薪项变化检测（8 类逐项比对，变了才走 changeFact）
    for (String type : FACT_TYPES) {
        String nv = dto.getFactValue(type);
        if (nv != null && !nv.equals(currentValue(old.getEmployeeId(), type))) {
            changeFact(old.getEmployeeId(), type, nv, dto.getEffectiveDate(), type, null);
        }
    }
}
```

### 4.3 `rebuildPostsAndRoles` 实现（★ 核心）

```java
@Override
public void rebuildPostsAndRoles(Long userId, List<String> postNames) {
    Long rootDeptId = tenantConfig.getRootDeptId();

    // 1. 岗位：先清后绑（多岗位）
    userPostMapper.deleteByUserId(userId);
    for (String name : postNames) {
        SysPost post = postMapper.selectByNameAndDept(name, rootDeptId);
        if (post == null) { post = createPost(name, rootDeptId); }  // 兜底建
        userPostMapper.insert(userId, post.getPostId());
    }

    // 2. 角色：岗位名=角色名，逐个匹配（多角色，不取主岗位）
    userRoleMapper.deleteByUserId(userId);
    for (String name : postNames) {
        SysRole role = roleMapper.selectByRoleName(name);
        if (role != null) {                    // ★ 匹配不到 → 不绑、不报错
            userRoleMapper.insert(userId, role.getRoleId());
        }
    }
}
```

## 五、员工导入（★ V6.0 回迁 · 本域自建）

### 5.1 归属澄清

| 项 | 结论 |
|----|------|
| 谁做员工导入 | **`panjia-people` 本域** |
| 与 `panjia-import` 关系 | **无业务调用**；import 域只做业绩/考勤/积分/费用单据 |
| 复用什么 | **仅复用 `common-import-util` 工具层**（解析/模板/归档/基础校验） |
| 复用什么（本域内） | Port-Adapter、`salary_fact` 闭开区间变更入口、`change_log` |
| 发不发 import 域事件 | **不发**（员工导入不产生 import 域事件） |

### 5.2 两阶段执行（业务落地 = 单一大原子事务）

```
┌─ 阶段 A：诊断（独立小事务）─────────────────────────┐
│ 1. common-import-util: archive → storagePath+hash   │
│ 2. common-import-util: resolve 模板（EMPLOYEE）      │
│ 3. common-import-util: parse → ParsedSheet           │
│    （含 rawValues 原始字符串 + 基础格式错误）         │
│ 4. 落 pj_people_import_batch(PARSING)               │
│ 5. 逐行落 pj_people_import_raw（raw_json）           │
│ 6. 业务校验（工号唯一/门店/师傅/职级枚举）→ issue     │
│ 7. 有阻断性 issue → 批次 FAILED，issue 保留供排查     │
└──────────────────────────────────────────────────────┘
                    ↓ 校验全通过
┌─ 阶段 B：落地（★ 单一大原子事务）───────────────────┐
│ 逐行：                                              │
│  1. DeptPort.ensureDept(dept_full)  → 自动建部门树   │
│  2. AccountPort.createUser(code,name,dept) → sys_user│
│  3. INSERT pj_people_employee（回填 user_id）        │
│  4. 生成 8 条 salary_fact（change_field=ALL）        │
│  5. AccountPort.rebuildPostsAndRoles(postNames)     │
│  6. 写 pj_people_change_log（IMPORT）                │
│ 7. 刷新 pj_people_salary_record                      │
│                                                      │
│ ★ 任一行/任一步失败 → 整批回滚，不留半成品 → FAILED  │
└──────────────────────────────────────────────────────┘
                    ↓ 全部成功
              批次 SUCCESS
```

**伪码：**

```java
public Long importEmployees(MultipartFile file) {
    // ---- 阶段 A：诊断 ----
    ArchiveResult ar   = fileArchiver.archive(file.getBytes(), file.getOriginalFilename(), "people");
    ImportTemplate tpl = templateResolver.resolve("EMPLOYEE");
    ParsedSheet sheet  = fileParser.parse(file.getInputStream(), tpl, file.getOriginalFilename());

    Long batchId = createBatch(PARSING, tpl, ar, sheet);      // 独立小事务
    rawMapper.batchInsert(toRawRows(batchId, sheet));         // 落 raw_json
    List<Issue> issues = businessValidate(sheet);             // 业务校验
    if (hasBlocking(issues)) {
        issueMapper.batchInsert(issues);
        batchMapper.updateStatus(batchId, FAILED);
        return batchId;
    }

    // ---- 阶段 B：单一大原子事务 ----
    try {
        employeeImportTxService.applyAll(batchId, sheet);     // @Transactional，见下
        batchMapper.updateStatus(batchId, SUCCESS);
    } catch (Exception e) {
        batchMapper.updateStatus(batchId, FAILED);            // 事务已回滚
        throw e;
    }
    return batchId;
}

@Transactional   // ★ 单一大原子事务
public void applyAll(Long batchId, ParsedSheet sheet) {
    for (ParsedRow row : sheet.getRows()) {
        Long deptId = deptPort.ensureDept(row.get("dept_full"));
        Long userId = accountPort.createUser(CreateUserCmd.of(row, deptId));
        Employee emp = insertEmployee(row, deptId, userId);
        for (String type : FACT_TYPES) {                       // 8 条 fact
            insertFact(emp.getEmployeeId(), type, row.get(type), row.get("hire_date"), "ALL", batchId);
        }
        accountPort.rebuildPostsAndRoles(userId, split(row.get("post_names"), "/"));
        changeLogMapper.insert(ChangeLog.importLog(emp, batchId));
    }
}
```

### 5.3 员工导入状态机（本域独立）

```
PARSING ──▶ VALIDATING ──▶ IMPORTING ──▶ SUCCESS
                │              │
                └──▶ FAILED ◀──┘  （终态，只能新建批次重试）
```

| 状态 | 说明 |
|------|------|
| `PARSING` | 解析中（工具层解析 + 落 raw） |
| `VALIDATING` | 业务校验中（工号唯一/门店/师傅/枚举） |
| `IMPORTING` | 单一大原子事务落地中 |
| `SUCCESS` | 导入成功 |
| `FAILED` | 终态：只能新建批次重试，禁止回退 |

> 与 import 域单据状态机（`PARSING→NORMALIZING→PENDING_CONFIRM→ARCHIVED`）**完全独立**，不复用。

### 5.4 校验与 issue 类型

| issue_type | 说明 | 阻断 |
|-----------|------|------|
| `REQUIRED_MISSING` | 必填缺失 | ✅ |
| `COLUMN_TYPE_ERR` | 类型转换失败 | ✅ |
| `DUPLICATE_CODE` | 工号重复（文件内 + 库内） | ✅ |
| `DEPT_PATH_INVALID` | 部门路径非法 | ✅ |
| `LEVEL_INVALID` | 职级不在枚举 | ✅ |
| `MENTOR_NOT_FOUND` | 师傅工号不存在 | ✅（可忽略） |
| `POST_NOT_FOUND` | 岗位名在 `sys_post` 不存在 | ❌（兜底建 + 告警） |

### 5.5 重复导入策略（SUPERSEDED · 本域独立）

**与 import 域单据策略不同 —— 主数据不物理删除：**

| 域 | 重复导入策略 |
|----|-------------|
| `panjia-import`（单据） | 旧批次 RawData 保留 + `SUPERSEDED` 过滤（**逻辑失效**） |
| **`panjia-people`（员工）** | 旧批次标记 `superseded_by_batch_id`；**员工业务对象不删除**，按 `employee_code` upsert + 变化的算薪项走 `changeFact()`（**结束旧 fact + 新增**），保护历史可追溯 |

> **理由**：员工有历史（职级变更、离职、算薪记录），物理删除会破坏 `salary_fact` 闭开区间与下游快照溯源。演进而非删除，符合"复用变更通用入口"。

## 六、对账（一致性兜底）

**为什么需要：** 不改动 RuoYi 前提下无法禁止管理员后台改 `sys_user`。people 是事实源头，对账 = **people 单向覆盖 sys_user**。

| people 侧 | sys_* 侧 | 处理 |
|-----------|----------|------|
| `employee.dept_id` | `sys_user.dept_id` | 不一致 → 覆盖 |
| 期望岗位集合 | `sys_user_post` | 不一致 → 重建 |
| 推导角色集合 | `sys_user_role` | 不一致 → 重建（匹配不到不覆盖） |
| `status=LEFT` | `sys_user.status` | 离职 → 禁用 |

> **不碰 `sys_role_dept`**（预置不改）。

**触发：** 手动按钮（主，算薪前点一次）+ 每日定时（备）。

## 附录 B：关键决策速查

| 问题 | 答案 |
|------|------|
| 员工导入谁做？ | **people 域本域**，不调 import 域 |

| 导入发事件吗？ | **不发** import 域事件 |

| 岗位匹配不到角色？ | 不绑不报错，HR 后台手动赋权 |
| 社保基数/比例存哪？ | **payroll 规则**，人身上只有开关 |
