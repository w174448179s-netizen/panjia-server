## 改动分类说明

### 配置类改动（不涉及业务逻辑）

| 序号 | 说明 |
|------|------|
| 1-3 | 根 POM 添加 panjia 版本属性、聚合模块声明、依赖管理。属 Maven 坐标层面，不修改 Java 源码包名 |
| 4-5 | ruoyi-admin 添加 panjia 模块依赖和 Flyway 依赖，使应用启动时加载盘家自动配置和数据库迁移。依赖通过 `@AutoConfiguration` 机制注册，不修改底座组件扫描路径 |
| 6-9 | 数据源配置从 MySQL 切换至 PostgreSQL（dev/prod 环境配置 + Docker 容器 + Flyway 激活）。属环境配置层面，不修改 Java 源码包名 |

### 底座源码包名（零修改保证）

- `org.dromara.**` 包名：**零修改**，所有底座 Java 源码包名保持不变
- `ruoyi-*` 目录中：**不出现** `com.panjia` 包
- 盘家代码全部位于 `panjia-modules/` 目录，包名 `com.panjia.**`

## 升级验证检查清单

每次底座升级时，逐项检查以下内容：

- [ ] 本清单中所有改动文件在新版本中是否仍可合并
- [ ] 根 POM 的 `panjia.version`、`archunit.version` 属性是否保留
- [ ] 根 POM 的 `panjia-modules` module 声明是否保留
- [ ] 根 POM 的 panjia 依赖声明是否保留
- [ ] ruoyi-admin/pom.xml 的 panjia 依赖和 Flyway 依赖是否保留
- [ ] application.yml 的 Flyway 配置是否保留
- [ ] application-dev.yml / application-prod.yml 的 PostgreSQL 数据源是否保留
- [ ] docker-compose.yml 的 PostgreSQL 容器是否保留
- [ ] ArchUnit 守卫测试是否通过
- [ ] Flyway 双链路验证是否通过
