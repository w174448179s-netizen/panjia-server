## 〇、核心约定（一次说清，后文不再重复）

### 0.1 一句话目标

> **一套员工主数据 + 算薪事实模型；换客户不改代码，只改导入数据与规则配置。**

### 0.2 事实 vs 规则（冻结）

**绑定到人（`salary_fact`，只有开关/标签/关系）：**

`level_code` / `status` / `social_insured` / `housing_insured` / `commercial_insured` / `dormitory` / `is_part_time` / `mentor_employee_id`

**归客户级规则（`rank_rule.rule_content` JSONB，payroll 域）：**

社保基数、社保比例（个人/公司）、公积金金额、公积金比例、兼职豁免、徒弟奖励上限。

> 换客户 = 只改规则 JSON，人身上 0 改动。

### 0.3 岗位与角色模型（★ 本次对齐）

#### 0.3.1 四个前提（对齐 RuoYi 权限结构）

| RuoYi 结构 | 语义 | people 如何维护 |
|------------|------|----------------|
| `sys_dept` | 部门树（门店/组别） | 导入时按 `门店-组别` 自动建 |
| `sys_post` | **岗位**（挂在**客户根节点**下） | 初始化已建好，导入只查不建 |
| `sys_user_post` | 用户-岗位关联（1:N，一个员工多个岗位） | Port **先清后绑** |
| `sys_user.dept_id` | 用户**归属部门**（N:1，单值） | Port 同步，与 `employee.dept_id` 一致 |
| `sys_user_role` | 用户-角色关联（1:N，一个员工多个角色） | Port **先清后绑** |
| `sys_role` | **角色**（全局，与岗位同名） | 初始化已建好 |
| `sys_role_dept` | 角色-部门（数据权限范围） | **预置，people 不改** |

#### 0.3.2 关键结论（冻结）

1. **岗位挂在客户根节点下**（如「富房」），不挂到具体门店；
   - 所有门店的员工选"经纪人"，指向**同一个 `post_id`**；
   - 初始化脚本已建好根部门 + 岗位，**无需按门店动态建岗位**。
2. **岗位名 = 角色名**（初始化时对齐建好）：
   - `sys_post.post_name = '经纪人'` ↔ `sys_role.role_name = '经纪人'`；
   - 匹配规则：**岗位名 → 同名角色**（精确匹配 `role_name`）。
3. **多岗位 → 多角色（1:1 展开）**：
   - 选了 N 个岗位 → 绑 N 条 `sys_user_post` + N 条 `sys_user_role`；
   - **不取主岗位、不做单值收敛**。
4. **匹配不到的处理**：
   - 岗位在 `sys_post` 中查不到 → 视为初始化缺失，**兜底动态建**（挂根节点）；
   - 角色在 `sys_role` 中查不到同名项 → **不绑该角色**，不抛异常；
   - HR 若认为应有权限，自行去 RuoYi 后台给该角色赋权，系统不强制覆盖。
5. **Employee 表不存 `position`、`role_id`**：
   - 岗位/角色全部以 `sys_*` 为唯一事实源；
   - Employee 只存 `dept_id`（归属）+ `user_id`（关联 sys_user）。

#### 0.3.3 权限链条

```
sys_user ──N:1── dept_id ──→ sys_dept（归属部门）
         │
         ├──1:N── sys_user_post ──N:1── sys_post（岗位，挂根节点）
         │
         └──1:N── sys_user_role ──N:1── sys_role（角色，全局）
                                              │
                                              └──→ 菜单权限 + 数据权限（sys_role_dept，预置）
```

> **人 → 岗位 → 角色 → 数据权限 → 部门。**
> 角色的菜单权限、数据权限范围由管理员在初始化/后台配好；导入修改只做"给用户分配岗位"，角色随之推导，**不管角色能管哪些部门**。

### 0.4 初始化（已就绪，设计只做对齐）

初始化脚本已手工完成，本设计**不再重复设计**，仅对齐约定：

| 项目 | 谁建 | 说明 |
|------|------|------|
| 客户根部门 | 初始化脚本 | `dept_id = ${root-dept-id}`（配置化） |
| `sys_post`（经纪人/店长/总监…） | 初始化脚本 | **挂在根部门下** |
| `sys_role`（经纪人/店长/总监…） | 初始化脚本 | **与岗位同名** |
| `sys_role_dept` 数据权限 | 初始化脚本 | 默认本部门及以下，总监全公司 |
| 门店/组别 | 导入时自动建 | 按 `门店-组别` 分隔 |
| 员工 + 账户 | 导入/新增时建 | 见 §四、§五 |

应用配置锁定根节点，供 Port 查询岗位使用：

```yaml
panjia:
  tenant:
    root-dept-id: 1   # 客户根部门 ID（与初始化脚本一致）
```

### 0.5 菜单与权限

**一个菜单「员工管理」**，基本信息 + 算酬配置全在一个弹窗（职级/社保/公积金/商保/宿舍/兼职/师傅 **HR 维护**）。

| 角色 | 权限 | 说明 |
|------|------|------|
| HR / 管理员 | 编辑 | 全字段可改 |
| 算薪组 | 只读 | 查看核对，需改找 HR |
| 经纪人/店长 | 仅本人 | 不进后台 |

> 不做独立"算薪编辑"菜单、不做独立"调岗"功能。

### 0.6 三不原则

1. **不直连 `sys_*`：** 全部走 Port，people 域零 `import com.ruoyi.*`；
2. **不改 RuoYi 基础代码：** 不拦后台编辑，改用**对账兜底**；
3. **不做员工导入自建批次：** 走导入域（EMPLOYEE source_type）。

### 1.3 pj_people_salary_fact（★ 算薪用，一项一条，闭开区间）

```sql
CREATE TABLE pj_people_salary_fact (
    fact_id        BIGINT       PRIMARY KEY,
    employee_id    BIGINT       NOT NULL,
    fact_type      VARCHAR(16)  NOT NULL,   -- 8 类枚举
    value          VARCHAR(128) NOT NULL,   -- 按 fact_type 解析
    effective_date DATE         NOT NULL,   -- 闭
    expire_date    DATE,                    -- 开，NULL=至今
    change_field   VARCHAR(32)  NOT NULL DEFAULT 'ALL',
    create_time    TIMESTAMP    NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_fact_emp_type ON pj_people_salary_fact(employee_id, fact_type);
CREATE INDEX idx_fact_timerange ON pj_people_salary_fact(effective_date, expire_date);
```

**fact_type 枚举（冻结 8 类）：**

| fact_type | value 含义 | 示例 |
|-----------|-----------|------|
| LEVEL | 职级编码 | A2 / S1 |
| STATUS | 状态 | ACTIVE/PARTTIME/LEFT |
| SOCIAL | 是否参保 | true/false |
| HOUSING | 是否缴公积金 | true/false |
| COMMERCIAL | 是否买商业保险 | true/false |
| DORMITORY | 是否住宿舍 | true/false |
| PARTTIME | 是否兼职 | true/false |
| MENTOR | 师傅员工 ID | 1000148441 |

> 无 HOUSING_AMOUNT / SOCIAL_BASE / SOCIAL_RATIO——金额比例全在规则侧。

**闭开区间协议：** `[effective_date, expire_date)`，取数 SQL：

```sql
SELECT value FROM pj_people_salary_fact
WHERE employee_id = :empId
  AND fact_type = :factType
  AND effective_date <= :point
  AND (expire_date IS NULL OR :point < expire_date)
ORDER BY effective_date DESC
LIMIT 1;
```

## 二、变更模型

### 2.1 通用变更方法（所有改动走这一个入口）

```java
@Transactional
public void changeFact(Long empId, String factType, String newValue, LocalDate effect) {
    // 1. 结束旧记录
    for (SalaryFact f : repo.findActive(empId, factType, effect)) {
        f.setExpireDate(effect);
    }
    // 2. 新增记录
    repo.add(new SalaryFact(empId, factType, newValue, effect, null, factType));
    // 3. 刷新 salary_record
    recordRefresher.refresh(empId, factType, newValue);
    // 4. 写日志
    logRepo.add(new ChangeLog(empId, factType, oldValue, newValue, effect, null, currentUser));
}
```

**分字段独立时间线：** 改职级只动 LEVEL，改保险只动 COMMERCIAL，生效时间各自独立。

### 2.2 入职 = 生成初始 fact

导入/手动新增走同一个方法：为 8 个算薪项各生成一条，`change_field='ALL'`，`effective_date=hire_date`。**不单独初始化。**

### 2.3 修改员工 = 统一变化检测（★ 核心）

**一个保存按钮，统一 diff——不做独立调岗。**

```java
@Transactional
public void updateEmployee(Long empId, EmployeeUpdateDTO dto) {
    Employee emp = repo.get(empId);
    LocalDate today = LocalDate.now();
    List<FieldChange> changes = diff(emp, dto);   // 比对所有字段

    for (FieldChange c : changes) {
        changeFact(empId, c.getFactType(), c.getNewValue(), today);
        // ① 归属部门变了 → 同步 sys_user.dept_id
        if (c.isDept())      accountPort.updateDept(emp.getUserId(), dto.getDeptId());
        // ② 岗位集合变了 → 重建 sys_user_post + 推导重建 sys_user_role
        if (c.isPosts())     accountPort.rebuildPostsAndRoles(emp.getUserId(), dto.getPostNames());
    }
    repo.update(emp.apply(dto));
}
```

**DTO 字段（岗位改为集合）：**

```java
public class EmployeeUpdateDTO {
    private Long deptId;                  // 归属部门
    private List<String> postNames;       // ★ 岗位名集合（多选，如 ["经纪人","培训师"]）
    private String levelCode;
    private Boolean socialInsured;
    // ... 其他算薪开关
    private LocalDate effectiveDate;
}
```

**规则：**
- 未变化字段不动；
- **归属部门 / 岗位集合变更 → Port 同步 sys_user**；职级/社保开关等 → 只走 fact，不同步账户；
- 职级只改 fact（算薪选择器，与登录/权限无关）。

## 四、Port-Adapter（员工↔账户同步，同事务）

### 4.1 包结构

### 4.2 Port 接口（domain 层，零 RuoYi）

```java
public interface AccountPort {
    /** 创建系统账户，返回 sys_user.id */
    Long createUser(String username, String nickname, Long deptId, List<String> postNames);
    void updateDept(Long userId, Long deptId);          // 改归属部门
    void rebuildPostsAndRoles(Long userId, List<String> postNames); // ★ 重建岗位 + 推导重建角色
    void disableUser(Long userId);                       // 离职禁用
}

public interface DeptPort {
    Long ensureDept(String deptFull);   // "门店-组别" 自动建树，返回最末级 dept_id
}

public interface PostRolePort {
    /** 岗位名 → sys_post（挂根节点，查不到则兜底动态建） */
    Long resolvePost(String postName);
    /** 岗位名 → 同名 sys_role.role_id（查不到返回 null，不绑不报错） */
    Long resolveRole(String postName);
}
```

### 4.3 rebuildPostsAndRoles 实现（★ 核心）

```java
@Transactional   // 与 people 同一事务
public void rebuildPostsAndRoles(Long userId, List<String> postNames) {
    // 1. 重建 sys_user_post（先清后绑，多岗位）
    userPostMapper.deleteByUserId(userId);
    for (String name : postNames) {
        Long postId = postRolePort.resolvePost(name);   // 查不到兜底建
        userPostMapper.insert(userId, postId);
    }

    // 2. 由岗位名集合 1:1 推导角色，重建 sys_user_role（先清后绑，多角色）
    List<Long> roleIds = postNames.stream()
        .map(postRolePort::resolveRole)
        .filter(Objects::nonNull)
        .distinct()
        .collect(Collectors.toList());

    userRoleMapper.deleteByUserId(userId);
    for (Long roleId : roleIds) {
        userRoleMapper.insert(userId, roleId);
    }
    // 匹配不到的角色：不绑、不报错、不覆盖——尊重后台手动赋权
}
```

**SQL（等价于）：**

```sql
-- 岗位：先清后绑
DELETE FROM sys_user_post WHERE user_id = #{userId};
INSERT INTO sys_user_post(user_id, post_id) VALUES
 (#{userId}, #{postId1}), (#{userId}, #{postId2});

-- 角色：先清后绑（由岗位名→同名角色推导）
DELETE FROM sys_user_role WHERE user_id = #{userId};
INSERT INTO sys_user_role(user_id, role_id) VALUES
 (#{userId}, #{roleId1}), (#{userId}, #{roleId2});
```

> **不存在"取主岗位"逻辑**——岗位与角色严格 1:1 展开，N 个岗位即 N 个角色。

### 4.4 导入/新增事务伪码（走 EmployeeImportSink）

```java
@Transactional   // people 域事务
public EmployeeImportResult sink(List<ValidatedRow> rows) {
    List<Long> createdIds = new ArrayList<>();
    try {
        for (ValidatedRow row : rows) {
            Long deptId = deptPort.ensureDept(row.getDeptFull());      // ① 建部门树
            Employee emp = employeeRepo.save(row.toEmployee(deptId)); // ② 建员工
            createdIds.add(emp.getId());
            Long uid = accountPort.createUser(                         // ③ 建账户 + 岗位 + 角色
                    row.getCode(), row.getName(), deptId, row.getPostNames());
            emp.setUserId(uid);
            employeeRepo.update(emp);
            factInitializer.init(emp.getId(), row);                    // ④ 8 条 fact
            logRepo.add(ChangeLog.ALL(emp.getId(), row.getHireDate())); // ⑤ 日志
        }
        return EmployeeImportResult.success(createdIds);
    } catch (Exception e) {
        cleanup(createdIds);   // 反向清理（删除已建员工，sys_* 随事务回滚）
        throw e;
    }
}
```

**一个事务内：** 部门树 + Employee + sys_user + sys_user_post + sys_user_role + 8 条 fact + log。

### 4.5 部门自动建

```java
public Long ensureDept(String deptFull) {
    Long parentId = rootDeptId;   // 从配置读取客户根节点
    for (String name : deptFull.split("-")) {   // "云庭店-花照云庭店A组"
        parentId = deptPort.ensureDept(parentId, name.trim());
    }
    return parentId;   // 返回最末级（组别）dept_id
}
```

模板约定：第一级=门店，第二级=组别，用 `-` 分隔，不存在自动新建。

## 五、导入（走导入域）

员工导入收敛到导入域 `source_type=EMPLOYEE`（第 6 个数据源），完整方案见《员工导入融合设计》。**people 域不提供导入接口、不建导入批次表。**

**流程：**

```
① 前端上传 Excel → 导入域 /panjia/import/upload?sourceType=EMPLOYEE
② 导入域：建批次(PARSING) → EmployeeDataSource.parse() → 落 pj_import_raw_employee
③ EmployeeNormalizer → 类型转换 → 回调 EmployeeImportSink.receive()
④ people Sink：建部门树 + Employee + sys_user + 岗位/角色(sys_user_post/sys_user_role) + 8 条 fact + log
⑤ 事务成功 → 批次 ARCHIVED；失败 → 清理 + 批次 FAILED
```

**导入模板（Excel 列）：**

| 列 | 字段 | 必填 | 说明 |
|----|------|:----:|------|
| 门店-组别 | dept_full | ✅ | `云庭店-花照云庭店A组` |
| 工号 | employee_code | ✅ | 唯一，= 系统账号 |
| 姓名 | employee_name | ✅ | |
| 职位 | post_names | ✅ | 岗位名，可多个用 `/` 分隔（如 `经纪人/培训师` → 岗位 + 角色各绑两个） |
| 职级 | level | ✅ | A0~A5/S1/S2 |

## 六、对账（一致性兜底）

**为什么需要对账：** 不改动 RuoYi 前提下，无法禁止管理员在后台改 `sys_user`。people 是事实源头，对账 = people 单向覆盖 sys_user。

**覆盖项：**

| people 侧 | sys_\* 侧 | 处理 |
|-----------|-----------|------|
| `employee.dept_id` | `sys_user.dept_id` | 不一致 → 覆盖 |
| `postNames`（DTO/模板） | `sys_user_post` | 不一致 → 重建（rebuildPostsAndRoles） |
| 推导的角色集合 | `sys_user_role` | 不一致 → 重建（rebuildPostsAndRoles） |
| `status=LEFT` | `sys_user.status` | 离职 → 禁用账户 |

> **不碰 `sys_role_dept`**（角色-部门数据权限是预置的）。
> **匹配不到的角色不强制覆盖**——保留后台手动赋权。

```java
// POST /api/people/reconcile/run
public ReconcileResult reconcileAll() {
    List<Diff> diffs = new ArrayList<>();
    for (Employee emp : employeeRepo.findAll()) {
        SysUser user = sysUserMapper.selectById(emp.getUserId());

        // 1. 归属部门
        if (!emp.getDeptId().equals(user.getDeptId())) {
            accountPort.updateDept(emp.getUserId(), emp.getDeptId());
            diffs.add(Diff.of("dept", user.getDeptId(), emp.getDeptId()));
        }

        // 2. 岗位 + 角色（统一入口，先清后绑，匹配不到不覆盖）
        List<String> expectedPosts = loadPostNames(emp);   // 从期望事实源取岗位集合
        List<Long> actualPostIds = userPostMapper.selectPostIdsByUserId(emp.getUserId());
        List<Long> expectedPostIds = expectedPosts.stream()
            .map(postRolePort::resolvePost).collect(Collectors.toList());
        if (!expectedPostIds.equals(actualPostIds)) {
            accountPort.rebuildPostsAndRoles(emp.getUserId(), expectedPosts);
            diffs.add(Diff.of("posts/roles", actualPostIds, expectedPostIds));
        }

        // 3. 离职禁用
        if (LEFT.equals(emp.getStatus()) && user.isEnabled()) {
            accountPort.disableUser(emp.getUserId());
            diffs.add(Diff.of("status", "enabled", "disabled"));
        }
    }
    return new ReconcileResult(diffs);
}
```

**触发方式：** 手动按钮（主） + 每日定时（备）。算薪前点一次即可。

## 附录 B：关键决策速查

| 决策 | 结论 |
|------|------|
| Employee 是否存岗位/角色 | **否**，走 `sys_user_post` / `sys_user_role` |
| 岗位挂哪 | **客户根节点**下，初始化已建 |
| 岗位 ↔ 角色关系 | **同名匹配**（post_name = role_name），1:1 |
| 多岗位如何处理 | **多角色**，N 岗位 → N 条 post + N 条 role |
| 是否取主岗位 | **否**，严格 1:1 展开 |
| 匹配不到角色 | **不绑、不报错**，尊重后台手动赋权 |
| 同步方式 | Port-Adapter **同事务**（不用 Outbox/事件） |
| 角色-部门数据权限 | **预置**，people 不改（`sys_role_dept`） |
| 公积金 | 归客户级规则 |
| 菜单 | 一个「员工管理」，HR 全权，算薪组只读 |
| 调岗 | 不做独立功能，放修改里 |
